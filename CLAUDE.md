# CLAUDE.md — Shardling (3D)

Working rules for every Claude Code session in this repository. Read this file first, every session. The full product/technical specification lives in `BUILD_PROMPT.md` — this file tells you how to work; that file tells you what to build.

**Project:** Shardling — an original 3D momentum-physics platformer for the web. Roll a small soot-orb through floating ruins, collect all shards, reach the portal gate, don't touch anything sharp. Stack: TypeScript (strict) · Three.js · Rapier (`@dimforge/rapier3d-compat`) · `postprocessing` · Vite · Vitest · Zod. All geometry, materials, and audio are generated in code — this repo must never contain binary assets (no models, textures, or audio files).

---

## 1. Session protocol

**Start of session:** read this file → check the Phase Log (§10) for current state → run `npm run check` to confirm a green baseline → skim the relevant BUILD_PROMPT section for the task at hand.

**End of session:** `npm run check` green → commit (conventional message) → update the Phase Log (§10) with what changed and what's next → list any deviations from `BUILD_PROMPT.md` explicitly.

Never leave the repo in a red state between sessions. If a task is half-done, commit behind a clearly named branch and say so in the log.

## 3. Architecture map

```
main.ts → await RAPIER.init() → App (renderer, PostFX composer, DPR, screen stack)
  GameLoop ──── fixed 60 Hz physics accumulator → interpolated render transforms
  screens/ ──── DOM overlays: Menu · LevelSelect · Hud · Pause · LevelComplete
  game/GameScreen ── thin orchestrator only:
     loader(levels/data/*.json → Zod) → EntityFactory → entities
     LevelRunner (timer, shards, win/lose) · CameraRig (orbit/follow/occlusion)
     physics/ world · groups (bitmasks) · queries (shape-casts)

core/  App · GameLoop · EventBus (typed) · SaveManager (zod+migrations) · AudioSynth · InputManager · Device (lo/mid/hi tier)
gfx/   MeshFactory + MaterialFactory (ALL geometry & materials) · ParticleFactory (pooled) · PostFX (bloom/vignette) · BlobShadow
entities/ player (Player + PlayerStateMachine + PlayerVisuals) · hazards/ · Shard · Portal
sdk/   PortalSdk interface · NullSdk default · crazyGamesSdk (domain-gated)
```

Data flow: input → `InputManager` (camera-relative via `CameraRig.getYaw()`) → `Player` (forces) → Rapier step → events → `EventBus` → HUD/LevelRunner/Audio/VFX. DOM UI never reaches into gameplay objects; gameplay never touches the DOM.

## 4. Invariants (non-negotiable)

1. **Numbers live in `src/config/tuning.ts`; colors live in `src/config/palette.ts`.** A hex literal or gameplay constant anywhere else is a bug.
2. **Physics through forces.** Permitted direct velocity writes: jump, jump-cut, bouncer — nothing else. Never teleport dynamic bodies; never scale a physics body.
3. **Physics/visual separation.** Every entity = body/collider + a visual wrapper `Object3D`. Squash-stretch and effects touch wrappers only; render transforms are interpolated between physics steps.
4. **Zero binary assets.** New geometry → `MeshFactory`; materials/textures → `MaterialFactory` (canvas-generated only); sound → `AudioSynth`. Factories run at boot/level-build — never during gameplay frames.
5. **Typed `EventBus` is the only cross-module channel.** Add the event type first, then emit.
6. **Every entity cleans up:** `destroy()` removes Rapier bodies/colliders, disposes uniquely-owned geometries/materials, kills tweens/listeners. 20 level restarts under `?debug=1` → body and geometry counts stable.
7. **`GameScreen` stays thin** — orchestration only; logic belongs in systems/entities.
8. **All strings in `src/ui/strings.ts`** (i18n-ready).
9. **`npm run check` green before any commit.** No exceptions.
10. **Original IP only.** Never reference, imitate, or borrow names/layouts/assets from existing games — in code, comments, docs, or levels.
11. **Respect `reduceMotion`** in every new effect (shake, hit-stop, flashes, mote drift).
12. **The ball keeps CCD enabled** and static terrain stays merged per material — don't regress either while refactoring.

## 5. Playbooks

### Add a hazard

1. One-paragraph behavior spec (kill volume, motion, telegraph). Lethal silhouettes are serrated/sharp — danger reads by shape, never color alone.
2. Extend the Zod discriminated union in `levels/schema.ts` (+ schema test).
3. Mesh in `MeshFactory`, material tokens from `palette.ts`; class in `entities/hazards/`; wire in `EntityFactory`.
4. Collider: group `HAZARD`, sensor, kills via `player:died`. Exclude sensors from camera-occlusion and ground casts.
5. If it moves: kinematic **position-based** body driven with `setNextKinematicTranslation` (Rapier then carries riders natively) — never teleport the translation directly.
6. One teaching level before it appears in any combination level. Extend `validate:levels` if it adds invariants.

### Add a level

1. Copy the closest-difficulty JSON in `levels/data/`; grid unit 1 m, y-up, boxes = min-corner + size.
2. 3D rules: platform tops ≥ 1.5 u wide (worlds 1–2) · min gap 2 u · every landing target visible from its takeoff at default camera · first shard un-missable · no hazard kills before it's been seen · set `killY` below the lowest terrain · write `intendedPath`.
3. Register in `levels/registry.ts` → `npm run validate:levels` → hand-play it: full clear, die once on each hazard, and rotate the camera in the tightest spot to confirm it stays usable.
4. Difficulty follows the world's teaching curve (BUILD_PROMPT §1.10). New mechanic ⇒ its own teaching level first.

### Tune game feel / camera

`?debug=1`, adjust lil-gui, play 2–3 minutes, "copy as code" into `tuning.ts`, commit `feat(tuning): …` with one line on what changed in feel. Re-verify the §1.3 feel tests after any movement change; re-check wall occlusion after any camera change.

### Add a sound

New patch in `AudioSynth` (osc/noise + envelope, ±3% random pitch), triggered from an EventBus event, respects master volume/mute. SFX < 600 ms except ambience and the speed-mapped rolling loop.

### Add a UI screen

DOM overlay in `screens/`, strings from `strings.ts`, palette tokens for styling, keyboard + touch reachable, 220 ms fade, listens to EventBus only, removes all listeners on teardown.

## 6. Art & animation rules

Palette tokens only. Rounded = safe, sharp = lethal. The look = matte darks + emissive accents + selective bloom + fog — never asset detail. One bloom pass (half-res on mobile tier); no shadow maps on lo/mid tiers — `BlobShadow` carries landing readability and must never be broken. Everything eases (`cubicOut` default, `backOut` springs); feedback 70–250 ms, ceremonies ≤ 600 ms. Particles only from `ParticleFactory` pools (≤ 400 live). Static level geometry merged per material (terrain ≤ 3 draw calls); repeated small meshes (shards, spike teeth, motes) are instanced.

## 7. Testing & QA

Unit (Vitest, no Three/Rapier imports): level schema + every shipped level JSON · SaveManager (roundtrip / corruption / migration) · PlayerStateMachine (coyote, buffer, double-jump reset, jump-cut) · camera-relative input math (yaw 0/90/180/270°) · registry unlock logic.

Manual gate before ending any gameplay-touching session: restart ≤ 800 ms · ride a fast pingpong platform (no jitter, no drop) · tap-vs-hold jump heights differ · camera never clips through graybox walls · blob shadow correct over ledge edges · mute/volume/reduceMotion persist · `?debug=1` body + geometry counts stable across 20 restarts · touch controls still work.

## 8. Performance budgets

60 fps at 4× CPU throttle in the busiest level · initial payload (JS + WASM) ≤ 4 MB gzip (build fails above) · total dist ≤ 15 MB · draw calls ≤ 100 (terrain ≤ 3 via merging; instancing for repeats) · triangles ≤ 150 k · particles ≤ 400 live, pooled · zero per-frame allocations in hot paths (reuse Vector3/Quaternion scratch objects) · DPR capped by tier (max 2) · bloom half-res on mobile.

## 9. Known pitfalls

- **Rapier init is async:** `await RAPIER.init()` before creating the world; the `-compat` build exists to avoid Vite WASM-loading pain — don't swap it for the raw package.
- **Tunneling:** the ball moves fast; CCD stays on, and floors are ≥ 1 u thick. A "falls through platform" bug is almost always one of these two.
- **Kinematic platforms:** drive with `setNextKinematicTranslation` each physics step (Rapier computes velocity and carries riders). Setting the translation directly teleports and drops the player.
- **Ground check is a shape-cast,** not a single ray — a center ray misses on ledge edges and reports airborne while visibly grounded.
- **Three.js doesn't GC GPU memory:** `dispose()` geometries/materials/render-targets on level unload; shared factory materials are disposed only at app teardown. Watch the `?debug=1` geometry counter.
- **Resize/DPR:** renderer _and_ composer (and half-res bloom targets) must all resize together, with DPR re-clamped per tier — miss one and post-FX goes blurry or blank.
- **Interpolation, not physics-in-rAF:** physics steps at fixed 60 Hz via the accumulator; meshes lerp between the last two states. Stepping physics per render frame reintroduces jitter on 120/144 Hz displays.
- **AudioContext** requires a user gesture: create/resume on first input; guard every play call before init.
- **Canvas gestures:** `touch-action: none` on the canvas and `preventDefault` on Space/Arrows, or the host page scrolls/zooms while playing (portal requirement — wired in Phase 6/8).
- **localStorage can throw** (private mode/quota) — only `SaveManager` touches it.
- **Squash-stretch on wrappers only** — scaling a collider changes gameplay.
